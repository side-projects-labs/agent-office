# Interface language

The interface is Korean by default. Set `NEXT_PUBLIC_UI_LOCALE=en` (at build time) for
English. Tests pin English, so upstream tests keep asserting the original text.

Two small mechanisms:

- `t("key")` in `src/lib/uiText.ts`: a handful of keyed strings used by the avatar chat,
  approvals and the workspace picker.
- `tr("English text")` in `src/lib/i18n.ts`: the English text is the key and
  `src/lib/i18n/ko.ts` maps it to Korean. A missing entry simply stays English, so
  nothing breaks while translations catch up.

`tr()` wraps visible text in JSX and `title` / `placeholder` attributes. It does **not**
cover strings inside object literals (labels, wizard step names, error messages),
template strings, or static `aria-label`s (kept in English on purpose so tests and
assistive tooling stay stable). Those are still English.

## Adding or fixing a translation

```bash
node scripts/list-untranslated.js   # tr() strings with no Korean entry yet
```

Add `"English text": "한국어"` to `src/lib/i18n/ko.ts`. The key must match the text in
the source exactly. `tests/unit/i18n.test.ts` fails if an entry is stale (no longer
used by any `tr()` call) or empty, and if too many `tr()` strings are untranslated.

Sentences split around inline elements or values (`Selected backend: {value}`) are
translated piece by piece; leave a piece in English if a translation would read badly
next to the neighboring text.
